# מודול תמלול-קול לשלוחות ימות המשיח (Yemot Hamashiach)

מודול **Vercel Python** גנרי וחד-פעמי בפריסה: מעלים אותו פעם אחת ל-Vercel,
ואז כל שלוחה בכל מערכת ימות (גם מספר מערכות שונות!) יכולה להתחבר אליו
פשוט על ידי הגדרת `token` ו-`tts_path` משלה בקובץ ה-`ext.ini` של השלוחה.

## מה זה עושה (זרימת שיחה)

1. מאזין נכנס לשלוחה מסוג `type=api` שמוגדרת מול המודול הזה.
2. המודול מבקש מהמאזין להקליט הודעה (`הקלטה`).
3. אחרי ההקלטה: המודול **מוריד** את קובץ ה-wav מהשלוחה (Management API,
   פקודת `DownloadFile`), **מתמלל** אותו לעברית (Google Web Speech,
   כמו בקוד המקורי), ו**כותב** את הטקסט כקובץ `TTS` (`UploadFile`) בנתיב
   שהוגדר מראש בהגדרות השלוחה עצמה.
4. השיחה ממשיכה לשלוחת היעד שהוגדרה (או להודעת סיום פשוטה, כברירת מחדל).

כל זה קורה בתוך שתי קריאות API בלבד לאותה שלוחה - בדיוק כמו כל שלוחת
`type=api` רגילה.

## למה זה שונה מהקוד המקורי (`transcribe.py`)

| נושא | המקור | כאן |
|---|---|---|
| תפקיד | שירות תמלול "טיפש" - מקבל בייטי wav גולמיים בגוף הבקשה, מחזיר טקסט | שלוחת `type=api` שלמה: מקבלת קריאה מימות, מורידה את ההקלטה בעצמה, מתמללת, וכותבת TTS בחזרה |
| חיבור לימות | נעשה בקוד Node.js נפרד, לא כלול כאן | מובנה במודול עצמו (`DownloadFile`, `UploadFile`) |
| ריפוד שקט | `pydub` + `ffmpeg` | מודול `wave` המובנה של Python בלבד (**ללא תלות ב-ffmpeg**, כי סביבת Vercel Python הרגילה לא כוללת ffmpeg) |
| תמיכה במספר מערכות | לא רלוונטי (שירות פנימי) | כן - טוקן ונתיב יעד מגיעים כפרמטרים לכל שלוחה בנפרד |
| שפת תמלול, זמן ריפוד | `he-IL`, 500ms | זהה |


## פריסה ל-Vercel

1. מעלים את התיקייה הזו כ-repo ל-GitHub.
2. ב-[vercel.com](https://vercel.com) -> **Add New Project** -> מחברים את ה-repo.
3. Vercel מזהה אוטומטית פונקציית Python לפי `api/index.py` + `requirements.txt`.
   אין צורך ב-Build Command או Output Directory מיוחדים - להשאיר ברירת מחדל.
4. Deploy. הכתובת שתקבלו תהיה בערך:
   `https://<your-project>.vercel.app/api/index`
   (זו הכתובת שתגדירו כ-`api_link` בשלוחה - ראו בהמשך).
5. **מגבלת זמן ריצה**: תמלול קובץ קול יכול לקחת כמה שניות (הורדה +
   תמלול + העלאה). ב-`vercel.json` הוגדר `maxDuration: 30`. בתוכנית
   Hobby (חינמית) של Vercel זו התקרה המותרת; בתוכניות בתשלום ניתן
   להגדיל אם צריך הקלטות ארוכות יותר.

## הגדרת השלוחה בימות (`ext.ini`)

בתיקיית השלוחה שתרצו להפוך ל"שלוחת תמלול", יוצרים/עורכים את `ext.ini`:

```ini
type=api
api_link=https://<your-project>.vercel.app/api/index

; --- חובה: טוקן הניהול של המערכת שלכם (מספר_מערכת:סיסמה) ---
; ראו: הגדרות מערכת -> API בפאנל הניהול של ימות, כדי ליצור סיסמת API.
api_add_0=token=0700000000:MyPassword123

; --- חובה: הנתיב שבו יישמר קובץ ה-TTS עם תוצאת התמלול (בלי סיומת) ---
; המודול יוסיף לבד את הסיומת .tts
api_add_1=tts_path=ivr2:/4/M9

; --- רשות: שם קובץ ההקלטה שיישמר בשלוחה עצמה, ברירת מחדל 000 ---
api_add_2=record_file=000

; --- רשות: שלוחת יעד לניתוב אחרי סיום התמלול (go_to_folder) ---
; אם לא מוגדר - תושמע הודעת "התמלול הושלם" וניתוק.
api_add_3=next_folder=/4/1
```

> **חשוב - אבטחת הטוקן**: הטוקן מוגדר בקובץ הגדרות השלוחה בשרתי ימות
> (לא בקוד ולא בריפו ב-GitHub), ונשלח מימות למודול ב-Vercel רק בבקשות
> POST פנימיות בין השרתים. עדיין מומלץ: להגביל את משתמש ה-API בימות
> להרשאות המינימליות הנדרשות (הורדת/העלאת קבצים באותה שלוחה בלבד, אם
> קיימת אפשרות כזו בפאנל שלכם), ולסובב (rotate) את הסיסמה מדי פעם.

### שימוש בתוצאה - השמעת ה-TTS

אחרי שהמודול כתב את קובץ ה-TTS בנתיב `tts_path` (למשל `ivr2:/4/M9.tts`),
אפשר להשמיע אותו בכל שלוחה אחרת (כולל שלוחת היעד `next_folder`) פשוט
על ידי יצירת קובץ הודעה בשם התואם (`M9.tts` בתיקייה `/4`) - ימות יקריא
את תוכנו אוטומטית כשהשלוחה תגיע לקובץ הזה בתור. לחלופין, אפשר לבנות
שלוחת `read=file` המצביעה על אותו שם קובץ.

## בדיקות מומלצות לפני עלייה לפרודקשן

1. **הקלטה תקינה** - לוודא שתמלול קובץ קול ברור מחזיר טקסט הגיוני.
2. **הקלטה ריקה/שקט מוחלט** - לוודא שהמודול לא נופל (מחזיר `UnknownValueError`
   -> נכתב קובץ TTS ריק, השיחה ממשיכה כרגיל).
3. **טוקן שגוי** - לוודא שמוצגת למאזין הודעת שגיאה כללית (לא פרטי הטוקן!)
   ושהשגיאה המלאה מופיעה בלוגים של Vercel בלבד.
4. **הגדרות חסרות** (`token`/`tts_path` לא מוגדרים) - המודול צריך להחזיר
   הודעת שגיאה מיידית בלי לנסות לגשת ל-API של ימות.
5. **עומס/כמה שיחות במקביל** - Vercel מריץ כל בקשה בפונקציה נפרדת, כך
   שאין בעיית מצב-משותף (shared state) בין שיחות שונות.
6. **ניתוב אחרי סיום** - לוודא ש-`go_to_folder`/הודעת ברירת המחדל עובדים
   כמצופה, כולל timeout/נתק באמצע הקלטה.

## Rollback

אם יש בעיה בפרודקשן: להחזיר את השלוחה בימות לגרסה קודמת של `ext.ini`
(או פשוט למחוק את `api_link`/לשנות את ה-`type`), וב-Vercel ניתן לחזור
לכל Deployment קודם דרך "Instant Rollback" בלוח הבקרה - בלי לגעת בקוד.
